### Added
- SDK: `Lium.up(..., wait=True, timeout=600)` returns the ready `PodInfo` (a timeout raises a `LiumError` that names the still-billing pod).
- SDK: `Lium.pod_by_name(name)` (name, huid or id); `with lium.rental(executor_id=..., ...) as pod:` rents a pod for the block and always removes it — on return, on exception, and when it never became ready.
- SDK: `Lium.exec(..., timeout=)` raises `TimeoutError` and closes the channel; `Lium.exec(..., detach=True, log_path=)` starts the command under `nohup setsid … < /dev/null &` and returns `{"pid", "log_path", "command"}`; the launcher line lives in `lium.sdk.detach` (shared with `lium exec --detach`), checks that `setsid` and `bash` exist before forking, and the default log name `exec-<UTC stamp>-<id>.log` is unique per launch (`Lium.build_detached_command` is the SDK name for it). `rental()` also removes a pod the server created when the rent call itself raised.
- SDK: `Lium.gpu_stats(pod)` returns `GpuStats` per GPU from `nvidia-smi --query-gpu`; `Lium.parse_gpu_stats(text)` is the parser.
- SDK: `PodInfo`, `ExecutorInfo`, `Template`, `GpuStats` and the backup, restore, SSH-key and volume models have `to_dict()` (nested models included, plus derived fields such as `PodInfo.host`/`ssh_port` and `ExecutorInfo.gpu_model`); `RentResult` stays a plain dataclass.
- SDK: `env=` given to `exec(detach=True)` and `run_background()` travels over the session's stdin as one variable and is applied inside the job's login shell after its profile, so the value is never in a pod process's argv and the given value wins over a profile assignment.
