### Added
- `lium reset-gpu <pod> [--gpu N ...]` and `Lium.reset_gpu(pod, gpu_indices=None)` reset a pod's hung GPUs without recreating the pod (`POST /pods/{id}/reset-gpu`). Every process in the pod is stopped, files are kept; the command asks first (`--yes` skips it), prints a result per GPU (`--json` for machine output) and exits non-zero with the API's code when the reset is refused (`mig_enabled`, `reset_not_supported`, `gpu_reset_unavailable`, ...). `reset_gpu` returns a `GpuResetResult`; when a GPU fails it raises `LiumGpuOperationError` with each GPU's outcome (`gpus`) and `container_restarted`, which the command prints (and puts in the JSON error's `data`). The reset takes 1 to 2 minutes: the API starts it (`202` with a `request_id`) and the SDK polls `GET /pods/{id}/reset-gpu/{request_id}` every 3 s, so a long reset no longer ends in a `503` from the 60 s proxy timeout; the command shows the elapsed time while it waits. A server answer `timeout` raises `LiumServerError` (`gpu_reset_unavailable`); a poll that gets a 5xx or loses the connection is tried again until 330 s; no final status in 330 s, or a lost connection while the reset is sent, raises `LiumServerError` (`gpu_reset_timeout`), and the command then says the reset may still be running and how to check it, instead of "Retry". A backend that still answers `200` with the result is read as before.
