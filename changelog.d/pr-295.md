### Added
- `lium provider node register-token`, `node tier eligibility|set`, `node pause|resume` and `node listing [NODE_ID]`: the portal's Add Node token, Secure/Spot tier, new-rental pause and listing state from the terminal. `node listing` rows always carry `gpu_count` and `rented_gpu_count` (`null` from a portal that does not send them): a node rented in part stays `listed`, so `rented_gpu_count` is what says a renter is on it.
- `lium provider earnings`, `idle-pay [NODE_ID]` and `ledger`: daily earnings (with `--emissions`), idle-pay state per node and the daily ledger.
- `lium provider portal login --email you@example.com` signs in without a wallet; the password comes from `LIUM_PROVIDER_PASSWORD` (a hidden prompt on a terminal). Agents sign in with `LIUM_PROVIDER_TOKEN`, not Google; `--help` says so.
- `lium provider token create|list|revoke`, and `LIUM_PROVIDER_TOKEN` is sent as the Bearer token when set. Until the portal serves API tokens the commands answer `portal.not_supported` (exit 3). Tokens are managed from a signed-in session only: with `LIUM_PROVIDER_TOKEN` set they answer `portal.api_token_needs_session` (exit 6). Signed in by a token or a `portal login --email` session, `node list` and `billing list` scope to the hotkey the portal names for the account.
- `lium mine --json`: one JSON result on stdout, one JSON step event per line on stderr (`host.repo` … `host.validate`, `host.register`, `host.wait_listed`), failures with a stable `host.*` code (`host.port_in_use`, `host.docker_missing`, `host.preflight_failed`, …). `LIUM_OUTPUT=json` does the same.
- `lium provider config connect-discord` and the new `lium provider portal confirm-email` are one-time human steps: they answer `human.handoff_required` (exit 12) with one URL, a short code and the sentence to relay (`data.message_for_human`); `--wait [--timeout N]` polls until the person is done (exit 0) or the code expires (`human.handoff_expired`, exit 12). The person enters the code in the portal. `connect-discord` does this with `--wait` or under `--json`, `LIUM_OUTPUT=json` or `LIUM_NONINTERACTIVE=1`; in text mode without `--wait` it opens the browser link as it always has. `confirm-email` is new and uses the handoff in both modes. Until the portal serves handoff sessions they answer `portal.not_supported` (exit 3) with the old browser link in `data.legacy_browser_url`; `connect-discord --wait` in text mode then runs the old browser flow.
- `docs/exit-codes.md` documents both exit maps and when each applies (0–7, 10 blocked, 11 not listed, 12 a person has to act, 130 interrupted) and which old codes the new ones replace.

### Changed
- `lium provider portal whoami` works when signed in by `LIUM_PROVIDER_TOKEN` or a `portal login --email` session, not only a hotkey, in text mode as well as under `--json`. `--json` adds `auth_method` (`token`, `hotkey`, `email_session`) to the account fields; the text output names the sign-in on its first line and adds an `Auth Method` row, and is unchanged when the hotkey signed in. When several are set, the token wins, then the hotkey, then the e-mail session. Signed in nowhere, text mode now says "not signed in to the provider portal" with the three ways in (still `[ARG_INVALID]`, exit 1) instead of asking for `--hotkey` alone.
- In agent mode (`--json`, `LIUM_OUTPUT=json` or `LIUM_NONINTERACTIVE=1`) every `lium provider` command that needs a sign-in and finds none answers `auth.not_signed_in` (exit 6) with the three ways in and `legacy_code: ARG_INVALID`, instead of `ARG_INVALID` (exit 1). Plain text mode prints the old line and exits 1. `config set-email` and `config set-password` sign with the hotkey's wallet: in agent mode without a hotkey they answer `input.arg_invalid` (exit 2) saying so, also when a token or e-mail session is set; plain text prints the old `config commands require --hotkey` line (exit 1).
- `mine.sh` installs `lium.io[provider]`, so `lium provider …` works right after `lium mine`.
- Under `--json`, `lium provider` answers `net.unreachable` instead of `PORTAL_SERVER_ERROR` when nothing answers at the portal URL, and passes a portal refusal's own `detail.code` through in snake_case as `portal.<code>` (`portal.node_rented`), with the old code in `legacy_code`. Text mode prints the old code and wording (`[PORTAL_SERVER_ERROR] network error reaching portal: …`).
- In agent mode (`--json`, `LIUM_OUTPUT=json` or `LIUM_NONINTERACTIVE=1`, whichever is set), every `lium provider` and `lium mine status` error exits by the unified map, whatever its origin: `ARG_INVALID`, `PORTS_INVALID` and `CONFIG_MISSING` → 2, `HOTKEY_NOT_REGISTERED`, `PORTAL_AUTH_INVALID`, `PORTAL_AUTH_EXPIRED` and `PORTAL_FORBIDDEN` → 6, `WALLET_NOT_FOUND` and `PORTAL_NOT_FOUND` → 5, `PORTAL_RATE_LIMIT` and `PORTAL_AUTH_REFRESH_RACE` → 7, `SSH_*` → 4, a refused connection → 4 (`net.unreachable`); `docs/exit-codes.md` lists every code. Under `LIUM_NONINTERACTIVE=1` with text output stderr prints the namespaced code (`[auth.not_signed_in] …`) with the same exit; `config set-password` without `--password` is `input.arg_invalid` (exit 2) instead of a prompt; `lium mine --register` exits 2 for an unreadable token or a conflicting `-k` (was 1) and 11 for a node registered but not listed (was 2). Plain text mode (none of the three set) keeps every old exit status. `config connect-discord --json` exits 3 (`portal.not_supported`, with the old link in `data.legacy_browser_url`) instead of 0 until the portal serves handoff sessions.

### Fixed
- Under `--json`, `LIUM_OUTPUT=json` or `LIUM_NONINTERACTIVE=1` the provider persona gate ignores piped input and fails with `input.confirmation_required` (exit 2); use `--yes` or `LIUM_PROVIDER_ACK=1`. Text mode prompts as it always has. Ctrl-C in agent mode is `input.interrupted` (exit 130).
- `lium provider idle-pay` on an account created with e-mail or Google answers `portal.overview_not_for_custodied_account` with a hint instead of a bare 403; a wrong password on `portal login --email` names `LIUM_PROVIDER_PASSWORD` instead of the hotkey-token hint.
- `--wait` rides out a portal blip (5xx, 429, unreachable) with backoff until `--timeout`, and a handoff the portal answers 404 for is `human.handoff_expired`.
- `lium mine` under `--json` or `LIUM_NONINTERACTIVE=1` asks nothing: without `-k` it exits 2 with `input.input_required`; with `-k` it takes the default ports as `--auto` does. Text mode prompts as it always has.
