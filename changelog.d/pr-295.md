### Added
- `lium provider node register-token`, `node tier eligibility|set`, `node pause|resume` and `node listing [NODE_ID]`: the portal's Add Node token, Secure/Spot tier, new-rental pause and listing state from the terminal.
- `lium provider earnings`, `idle-pay [NODE_ID]` and `ledger`: daily earnings (with `--emissions`), idle-pay state per node and the daily ledger.
- `lium provider portal login --email you@example.com` signs in without a wallet; the password comes from `LIUM_PROVIDER_PASSWORD` (a hidden prompt on a terminal). Agents sign in with `LIUM_PROVIDER_TOKEN`, not Google; `--help` says so.
- `lium provider token create|list|revoke`, and `LIUM_PROVIDER_TOKEN` is sent as the Bearer token when set. Until the portal serves API tokens the commands answer `portal.not_supported` (exit 3). Tokens are managed from a signed-in session only: with `LIUM_PROVIDER_TOKEN` set they answer `portal.api_token_needs_session` (exit 6).
- `lium mine --json`: one JSON result on stdout, one JSON step event per line on stderr (`host.repo` … `host.validate`, `host.register`, `host.wait_listed`), failures with a stable `host.*` code (`host.port_in_use`, `host.docker_missing`, `host.preflight_failed`, …). `LIUM_OUTPUT=json` does the same.
- `lium provider config connect-discord` and the new `lium provider portal confirm-email` are one-time human steps: they answer `human.handoff_required` (exit 12) with one URL, a short code and the sentence to relay (`data.message_for_human`); `--wait [--timeout N]` polls until the person is done (exit 0) or the code expires (`human.handoff_expired`, exit 12). The person enters the code in the portal. Until the portal serves handoff sessions they answer `portal.not_supported` (exit 3) with the old browser link in `data.legacy_browser_url`; in a terminal `connect-discord` runs the old browser flow.
- `docs/exit-codes.md` documents both exit maps and when each applies (0–7, 10 blocked, 11 not listed, 12 a person has to act, 130 interrupted) and which old codes the new ones replace.

### Changed
- `mine.sh` installs `lium.io[provider]`, so `lium provider …` works right after `lium mine`.
- `lium provider` answers `net.unreachable` instead of `PORTAL_SERVER_ERROR` when nothing answers at the portal URL, and passes a portal refusal's own `detail.code` through in snake_case as `portal.<code>` (`portal.node_rented`), with the old code in `legacy_code`.
- Under `--json` or `LIUM_OUTPUT=json`, every `lium provider` and `lium mine status` error exits by the unified map, whatever its origin: `ARG_INVALID`, `PORTS_INVALID` and `CONFIG_MISSING` → 2, `HOTKEY_NOT_REGISTERED`, `PORTAL_AUTH_INVALID`, `PORTAL_AUTH_EXPIRED` and `PORTAL_FORBIDDEN` → 6, `WALLET_NOT_FOUND` and `PORTAL_NOT_FOUND` → 5, `PORTAL_RATE_LIMIT` and `PORTAL_AUTH_REFRESH_RACE` → 7, `SSH_*` → 4, a refused connection → 4 (`net.unreachable`); `docs/exit-codes.md` lists every code. Text mode keeps every old exit status. `config connect-discord --json` exits 3 (`portal.not_supported`, with the old link in `data.legacy_browser_url`) instead of 0 until the portal serves handoff sessions.

### Fixed
- Under `--json`, `LIUM_OUTPUT=json` or `LIUM_NONINTERACTIVE=1` the provider persona gate ignores piped input and fails with `input.confirmation_required` (exit 2); use `--yes` or `LIUM_PROVIDER_ACK=1`. Text mode prompts as it always has. Ctrl-C under `--json` is `input.interrupted` (exit 130).
- `lium provider idle-pay` on an account created with e-mail or Google answers `portal.overview_not_for_custodied_account` with a hint instead of a bare 403; a wrong password on `portal login --email` names `LIUM_PROVIDER_PASSWORD` instead of the hotkey-token hint.
- `--wait` rides out a portal blip (5xx, 429, unreachable) with backoff until `--timeout`, and a handoff the portal answers 404 for is `human.handoff_expired`.
- `lium mine` under `--json` or `LIUM_NONINTERACTIVE=1` asks nothing: without `-k` it exits 2 with `input.input_required`; with `-k` it takes the default ports as `--auto` does. Text mode prompts as it always has.
