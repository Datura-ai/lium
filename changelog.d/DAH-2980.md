### Fixed
- `lium up` with filters and a client-side pick (`--count`, `--country`, `--ports` without `--gpu`, or any filters against a backend without `rent_by_spec`) now rents, instead of the first node the API returned, the Pareto-optimal node with the lowest total `$/h` for what the rent takes (`--count` GPUs, else the node's free GPUs, at that node's `$/GPU`); the frontier is drawn among nodes renting the same count, so a cheaper-per-GPU 8× node neither beats nor hides an otherwise equal 1× node; fully booked or unpriced nodes are never the pick, and when every match is one the command fails before renting; it prints the selected node and its total `$/h` before renting, and the help text says so. `--gpu` on a current backend takes the server's pick (DAH-3047); explicit `NODE_ID` picks are unchanged. (DAH-2980)
