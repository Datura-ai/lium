### Fixed
- `lium up` with filters and a client-side pick (`--count`, `--country`, `--ports` without `--gpu`, or any filters against a backend without `rent_by_spec`) now rents row 1 of `lium ls` with the same filters, in the order `ls` prints (cheapest `$/GPU·h` first, nodes without a price last), instead of the first node the API returned; `up` has no ranking rule of its own: the ★ rule (the 100 Mbps floor, a 10 % faster download winning, spec dominance) no longer narrows this pick, so the cheapest `$/GPU·h` row is rented even when a dearer node downloads faster, as `ls` shows it. It prints the selected node and its `$/h` before renting, and the help text says so. `--gpu` on a current backend takes the server's pick (DAH-3047), and the spec it sends no longer adds a 100 Mbps download floor, so a node `lium ls --gpu X` shows is not skipped by `lium up --gpu X`. Explicit `NODE_ID` picks are unchanged. (DAH-2980)
