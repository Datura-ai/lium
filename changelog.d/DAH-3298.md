### Changed
- `lium up <index>` trusts a row number only while it still means what `lium ls` showed: the listing `ls` records (`~/.lium/last_selection.json`) now carries the shell that wrote it and a UTC time, and `up` refuses the number — `Run 'lium ls' and retry, or name the node by its huid` — when there was no `ls` in this shell, the listing is older than 10 minutes, or another shell (another agent in the same home directory) wrote it. Same rule as `lium rm <index>` (DAH-2559). `LIUM_NO_POD_INDEX=1` now also makes `up` refuse numbers.
