### Added
- Every failure now carries a hint (what to run next). The JSON error envelope gains `hint` and `exit_code`: `{"ok": false, "error": {"code", "message", "hint", "exit_code"}}`; in text mode the hint is printed under the error.
- `LIUM_OUTPUT=json` renders failures as the JSON envelope on every command, without a per-command flag.
- `docs/exit-codes.md` documents the exit codes, the envelope and the shared error codes; a unit test keeps it in step with the constants.
- SDK: a 403 for lack of funds raises `LiumInsufficientBalanceError` (a `LiumPermissionError`) with the `required`/`available` amounts parsed from the API's message when it states them. The platform's structured `error.code` (`insufficient_balance`) decides when the response carries one; the message text ("Insufficient balance") decides for older servers.
- `LIUM_DEBUG=1` prints the traceback of every handled failure to stderr, so the "re-run with LIUM_DEBUG=1" hints deliver. `fund`'s `transfer_failed` and `up`'s `jupyter_install_failed` carry hints that do not say "re-run" (a re-run would send TAO again or rent a second pod); `fund` renders `transfer_failed` through the shared handler, so `LIUM_OUTPUT=json` gets the envelope too.

### Changed
- SDK errors map to distinct codes: 401 → `invalid_api_key`, 404 → `not_found`, 429 → `rate_limited`, 5xx → `server_error` (all exit 3, as before), insufficient balance → `insufficient_balance` (exit 6). No existing exit code changes.
