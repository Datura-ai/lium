### Fixed
- After `lium provider portal login --email <address>` (or `--token`), `lium provider` commands such as `node list` and `node rm` act on that account, even when `provider.hotkey` is set in `~/.lium/config.ini`. Before, the config hotkey won, so they acted on another account or failed when that hotkey had no local wallet. The latest `portal login` now decides: a plain `portal login` switches back to the hotkey, and `--hotkey` or `LIUM_PROVIDER_HOTKEY` always wins. `portal logout` of the e-mail account or token returns to the config hotkey. `portal whoami` shows which one commands act on (`active_identity`). `provider.hotkey` is kept.
