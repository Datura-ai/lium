### Added
- `lium gpu-clocks <pod> --lock MIN,MAX | --reset [--gpu N ...]`, `Lium.lock_gpu_clocks(pod, min_mhz, max_mhz, gpu_indices=None)` and `Lium.reset_gpu_clocks(pod, gpu_indices=None)` lock a pod's GPU core clocks to a MHz range or return them to the default (`POST /pods/{id}/gpu-clocks`). Nothing in the pod is stopped and no confirmation is asked; the command prints the applied clocks per GPU (`--json` for machine output) and exits 3 with the API's code when the change is refused (`clock_lock_not_supported`, `mig_enabled`, `operation_in_progress`, `gpu_clocks_unavailable`, ...). Both calls return a `GpuClockResult`; when some GPUs fail they raise `LiumGpuOperationError` with every GPU's outcome (`gpus`), so the caller sees which stay locked, and the command prints that table (and puts it in the JSON error's `data`).
