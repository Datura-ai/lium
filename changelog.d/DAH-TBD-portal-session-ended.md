### Fixed
- `lium provider portal login` checks a cached token with the portal (`GET /auth/me`) and signs in again with the hotkey when the portal answers 401. The provider portal now ends every session of an account on **Log out everywhere**, a password or e-mail change and an admin revoke; the cached token used to be returned unchecked until its expiry, so every later `lium provider` command answered `portal rejected credentials`. An unreachable portal still leaves the cached token in use, as before.
- `lium provider config set-email` signs in with the hotkey first (the portal takes a new address only from a recent sign-in) and stores the session token the portal returns for the new address in place of the one it ended. The token is not part of the printed profile, `--json` included.
