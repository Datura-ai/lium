### Changed
- The SDK retries transient failures (429, 5xx, network errors) only for `GET`/`HEAD`/`OPTIONS`. `POST`, `PUT`, `PATCH` and `DELETE` — template, volume and backup creation, restore, reboot, pay-API transfers, every delete — are repeated only after a 429 (the server declined to run the request, so nothing was applied) and never after a 5xx or a lost connection, so a lost response no longer creates a duplicate or turns a completed delete into "not found". `_request(..., retry=True|False)` overrides the default per call. `schedule_termination`, `backup_cancel` and `restore_cancel` keep the full retry: their payloads are idempotent, so a repeat cannot double anything.
