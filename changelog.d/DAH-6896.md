### Fixed
- `lium provider` commands that cannot open the wallet (`WALLET_NOT_FOUND`) now say why: the message carries the underlying error, which names the keyfile path that was read and whether it was missing, unreadable or encrypted. Before, only the wallet and hotkey names were shown.
- A hotkey file that is password-encrypted and does not decrypt (a wrong password) now gets a "check the password" hint instead of "create a wallet".
- `lium provider` commands can open a hotkey file encrypted by the current btcli: the bundled bittensor-wallet goes from 4.0.1, which could not decrypt files encrypted by 4.1 even with the right password and reported the wallet as not found, to 4.1.0 (bittensor 10.5.0, bittensor-cli 9.23.2).
