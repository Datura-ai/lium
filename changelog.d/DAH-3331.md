### Changed
- `lium up --ttl` / `--until` schedule the pod's removal as soon as the rent returns a pod id, not once the pod is ready. A rent whose wait runs out (`--timeout`, `--ready-timeout`) or whose pod never starts used to leave a billing pod with no end time; now the removal is set first and the failure message names it. `--ttl` counts from the rent, not from when the flag was parsed (the node lookup and the confirmation prompt no longer eat into it). When the schedule call fails right after the rent, `up` says so, waits for the pod and tries once more when it is ready — the pod is kept either way. `Lium.schedule_termination()` accepts the pod id or the dict `up()` returns, so SDK callers can set the removal before `wait_ready()` too.
