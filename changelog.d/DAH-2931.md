### Added
- CLI: `lium up --timeout SECONDS` (default 900) is the budget for the whole command — finding the node, renting it and waiting for the pod. When it runs out before the rent, exit 1 with no pod created (`timeout_before_rent`); when it runs out while the pod is still starting, exit 1 with the pod named; `--ready-timeout` now caps only the wait within that budget.
- CLI: `lium up` prints what it is doing while it waits — `renting <node>…`, `pod <name> (id: …) created; waiting for it to become ready`, then `waiting for <pod>… <STATUS> (<n> s)` on every status change and every 30 s — so an agent behind a pipe can tell a slow rent from a dead one.
- CLI: a rent request the API never answers exits 3 with `api_timeout` and says to check `lium ps` before retrying (a pod may exist); a rent the API refuses exits 3 with `rent_rejected`, the node, the server's reason, a pointer to `lium ps` (the SDK retries an unanswered rent once, so a refusal can follow a request that did create a pod) and a pointer to `lium ls --format json`.
- SDK: `Lium.pod_events(pod_id)` (GET `/pods/{id}/events`, `[]` on older backends) and `Lium.pod_failure_cause(pod_id)`. `PodStartError.cause` carries the failure the backend recorded for the pod (the validator's headline, e.g. `... (failure_step: ssh_connect)`) and the message ends with `; cause: ...` when there is one.
- SDK: `Lium.wait_ready(..., on_poll=callback)` reports every poll (pod, status, seconds elapsed).

### Changed
- SDK: `CREATION_FAILED`, `BROKEN`, `REBOOT_FAILED` and `DELETING` — the backend's own dead-end statuses — are terminal for `wait_ready`, so a failed create is reported at once instead of being polled until its row is deleted.
