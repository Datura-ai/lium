### Added
- CLI: `lium init --api-key <key>` — headless authentication for agents, CI and containers. The key is checked against `/users/me`, saved to `~/.lium/config.ini` (mode 600) and the SSH key is set up; nothing opens a browser or waits for a person. `--json` prints the result (`ok`, `api_key_source` — the same value `lium whoami --json` prints: where the next command reads the key, an exported key or the active workspace's saved key winning over the saved account key —, `saved_from`, `env_key`, `active_workspace`, `config_path`, `ssh_key_path`); it needs `--api-key` or an exported `LIUM_API_KEY` / `LIUM_API_API_KEY`. With `LIUM_WORKSPACE` / `-w` set it exits 2 (`lium keys create … --workspace <ws> --save` saves a workspace key). A refused key exits 3 (`invalid_api_key`), an unreachable API exits 3 (`api_unreachable`), an empty value exits 2 (`empty_api_key`); nothing is saved in those cases.
- CLI: `lium init` with `LIUM_API_KEY` exported skips the browser flow and says the key is read from the environment (the SSH key path is still written to the config file, the key is not). A failed browser flow now names the headless way (`--api-key`, `LIUM_API_KEY`).

### Fixed
- CLI: every command crashed at start with `FileNotFoundError` when `$HOME` named a directory that did not exist yet (a fresh container); `~/.lium` is now created with its parents.
