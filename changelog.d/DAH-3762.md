### Added
- `lium topup card -a <USD> [--card <pm_id>] [--idempotency-key <key>] [--yes] [--json]` — charge a card saved on the account from an API key with the `billing` scope, no browser (not released: the platform switch is off). The command asks before charging; `--yes` skips the question and `--json` needs it. Sent once with an idempotency key; a lost answer or a 202 without a `payment_intent_id` exits 6 (`charge_outcome_unknown` / `charge_pending`) with the key and the same amount to re-run with (a different amount is a new charge). A 202 with a `payment_intent_id` is success (exit 0). SDK: `Lium.topup_card(amount_usd, payment_method_id=None, idempotency_key=None)`; `LiumCardTopUpError` for the route's 402s including `API_KEY_BUDGET_EXCEEDED`; `LiumChargeOutcomeUnknownError` for a lost answer (not for `nan`/`inf` amounts, and not for a 502 whose code is `STRIPE_UNAVAILABLE` or `STRIPE_REFUSED`).
