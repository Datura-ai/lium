### Added
- `lium up --budget USD`: auto-terminate once the pod has spent that much. The cap is computed client-side as `created_at + budget / price_per_hour` (the pod's own price; `created_at` is the one timestamp the API gives — the platform bills from RUNNING, so the cap errs a few start-up minutes early, never over) and scheduled through the same removal mechanism as `--ttl` (`lium schedules` lists it, `lium schedules rm` cancels it). It is set once the pod is ready — a pod that never becomes ready is not capped by `--budget`; `--ttl` holds from the rent and covers that. With `--ttl`/`--until` as well, the earlier deadline is used. A budget that buys less than 5 minutes, or a node without a price, is refused before anything is rented. If starting alone outlasts the runtime the budget buys, the pod is removed at once and `up` exits non-zero (`budget_exhausted`) instead of sending a past deadline, which the API rejects and would leave the pod running uncapped.
- SDK: `Lium.cap_spend(pod, budget_usd=…)` schedules the same removal for a running pod and returns the deadline; `lium.sdk.utils.spend_cap_deadline()` and `parse_api_timestamp()` are the underlying helpers.
- `lium ps`: the Spent column reads `$3.20/$12.50` when a removal is scheduled (spent so far against the spend at removal); `--format json` adds `spend_cap_usd` (null without a schedule).
