### Fixed
- `Lium.up(image=...)` checks for an SSH key before it creates the one-time template, so a call refused with "No SSH keys found" no longer leaves an `ephemeral-<hash>` template on the account.
- `Lium.backup_logs` and `Lium.restore_logs` (and so `lium bk logs`, `lium bk show` and the short restore id lookup) return every log of the pod, not only the first 20.
- `Lium.get_template` finds a template by HUID or name among the caller's own templates (someone
  else's public template is chosen by its ID, so a public look-alike name or HUID is never picked; when only a
  public template matches, the error names its ID and image), as its docstring says, instead of returning `None`; it returns `None` only when the template is not found and raises other errors.
- `Lium.wait_template_ready` returns a usable template (`CREATED`, `UPDATED` or `VERIFY_SUCCESS`) at once, and still waits on `VERIFY_PENDING`: the server does not verify user templates, so it used to wait out the whole timeout and return `None`.
- `ApiKeysClient.refusals` works with an API key alone: the key asks about itself when there is no browser session.
- The `ls(gpu_count=...)` docstring gives the real default (`None`, any count), and the API-key, `ps(api_key_id=...)` and budget docstrings no longer say "server support pending".
- `Lium.get_template` (and so `lium up -t <name>`) refuses a name or HUID that several templates share instead of taking the first one listed; pass the template's ID.
- The `lium keys` help, README, `docs/agents.md` and `docs/exit-codes.md` no longer say key budgets, scopes, pod visibility and refusals are "not on lium.io yet".
- `Lium.get_template` falls back to a template named like the UUID only among the caller's own templates, so a public template cannot take the place of a UUID that is not found.
- `Lium.exec` (and so `lium exec`) no longer hangs, or raises `TimeoutError` with a timeout, when a command prints more than about 2 MiB: it now reads stdout and stderr while it waits for the exit status.
- `Lium.exec` and `exec_all` keep at most `max_output_bytes` (default 64 MiB) bytes of output, stdout and stderr together, and `lium exec --max-output-bytes N` sets it from the CLI. It bounds output bytes, not memory: peak memory is about twice the limit for ASCII output (raw bytes plus decoded text). Past it the channel is closed and `OutputLimitExceeded` is raised, instead of a runaway command filling this process's memory.
