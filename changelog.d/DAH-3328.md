### Changed
- Releases follow SemVer from the changelog: `scripts/next_version.py` (`make next-version`) reads the `changelog.d/` fragments since the previous tag and prints the smallest next version (`### Added` or no header → minor, `### Removed` or a `BREAKING` bullet → major after 1.0, `### Changed` / `### Fixed` / `### Security` / `### Deprecated` → patch). The release workflow refuses a tag below that minimum before the wheel is built, so nothing is published, and names the tag to use; a line `allow-version-skip: <reason>` in the release notes lets a hotfix patch ship on top of unreleased features (RELEASING.md).
