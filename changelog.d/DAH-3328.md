### Changed
- Releases follow SemVer from the changelog: `scripts/next_version.py` (`make next-version`) reads the `changelog.d/` fragments and the `CHANGELOG.md` sections added since the previous tag and prints the smallest next version (`### Added` or no header → minor, `### Removed` or a `BREAKING` bullet → major after 1.0, `### Changed` / `### Fixed` / `### Security` / `### Deprecated` → patch). The release workflow refuses, before the wheel is built, a tag below that minimum, a tag not above the previous release, or code under `lium/` with no changelog entry, and names the tag to use. A hotfix below the minimum needs `allow-version-skip: <reason>` in the release notes and the skipped minimum committed in `changelog.d/.deferred_minimum` (`--defer`), which holds every later release to it (RELEASING.md). That file is seeded with `0.1.0`: the features shipped as patches in v0.0.42 … v0.0.46 make the next release 0.1.0.
