### Added
- `lium provider node resume --pause-id <uuid>` resumes new rentals only while that pause is still the node's current one: the portal otherwise changes nothing and the command fails with `node.pause_id_mismatch` (exit 3), the current pause in `error.data.current_pause_id` (a UUID or `null`). It reads the node first and, on a portal whose `node get` has no `pause_id` field (it would resume regardless), refuses with `portal.not_supported` (exit 3) and sends no resume. A malformed id is `input.arg_invalid` (exit 2 in agent mode; `ARG_INVALID`, exit 1, in plain text mode).
- `lium provider node pause --json` passes through `paused_by_this_call` (true only when this call set the pause) and `pause_id` (this call's own id then; on a node already paused, the existing pause's id, which may be `null`). A portal that does not send them gives `null` for both, never `false`.
- `node get --json` always carries `pause_id`, and `node listing --json` rows always carry `pause_id` and `new_rentals_pause_requested_at` (`null` when new rentals are not paused, or the portal does not send them). Plain text `node get` prints what it always has.
