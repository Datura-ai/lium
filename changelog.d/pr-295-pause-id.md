### Added
- `lium provider node resume --pause-id <uuid>` resumes new rentals only while that pause is still the node's current one: the portal otherwise changes nothing and the command fails with `node.pause_id_mismatch` (exit 3), the current pause in `error.data.current_pause_id` (a UUID or `null`). It reads the node first and, on a portal whose `node get` has no `pause_id` field (it would resume regardless), refuses with `portal.not_supported` (exit 3) and sends no resume. A resume answer without a `pause_id` field (a portal instance that does not check the id, during the portal's rollout) is `node.resume_unverified` (exit 12, `data.pause_id_checked: false`, `data.message_for_human`): the pause may have been lifted whatever its id, so a person checks the node. A malformed id is `input.arg_invalid` (exit 2 in agent mode; `ARG_INVALID`, exit 1, in plain text mode).
- `lium provider node pause --json` passes through `paused_by_this_call` (true only when this call set the pause) and `pause_id` (this call's own id then; on a node already paused, the existing pause's id, which may be `null`). A portal that does not send them gives `null` for both, never `false`.
- `node get --json` always carries `pause_id`, and `node listing --json` rows always carry `pause_id` and `new_rentals_pause_requested_at` (`null` by default). A `null` `pause_id` proves no pause: new rentals are not paused, the pause was set without an id, or the portal does not send it; `new_rentals_pause_requested_at` says whether new rentals are paused. Plain text `node get` prints what it always has.
