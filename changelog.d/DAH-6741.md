### Fixed
- `lium reset-gpu`: a reset the node refuses (`gpu_in_use_outside_pod`, `reset_not_supported`) no longer ends with "Retry; if it persists, re-run with LIUM_DEBUG=1". The `gpu_in_use_outside_pod` hint says to stop the named process if it is the renter's own and retry, otherwise to contact the provider; both hints point to picking a different node in `lium ls` and renting it with `lium up <node>`, and say the original pod stays rented and billing until it is removed with `lium rm <pod>`.
- `lium reset-gpu`: the `reset_not_supported` / `container_not_restarted` hint no longer says the node did not reset the GPUs, which is untrue when the GPUs were reset and only the container did not start again. The container warning says the reset did not start the container again instead of "is still stopped".
- `lium reset-gpu`: a failure whose hint points to another node names the node the pod is on, in the message and as `data.node` (`id`, `huid`) in `--json`, so it can be left out when picking from `lium ls`. The `gpu_in_use_outside_pod` hint says to contact support with the pod name if the container is not running or did not start, that the PID shown is the host's, and to stop the process only if it can be told apart from inside the pod, otherwise to give that host PID to the provider or support. The `reset_not_supported` / `container_not_restarted` hint says to contact support with the pod name if the container is not running or did not start. It also covers a container that "was not started", and says not to retry while the node reports the GPU reset still runs.
