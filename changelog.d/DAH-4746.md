### Added
- `lium provider portal login` signs in a provider account that has an authenticator app. When the portal asks for the code, the CLI prompts for it in a terminal ("Authenticator code (or a recovery code)"). Scripts pass it with `--totp-code <code>`, which also takes a recovery code. Without a terminal or `--totp-code`, the sign-in fails with `auth.totp_required` (exit 2). The same prompt appears when another provider command has to sign in again. `lium provider config set-email` needs two codes on such an account: it signs in again, and the portal asks for a second code for the new address. `--totp-code` answers the sign-in; a terminal is asked for the second one, and a script without a terminal fails with `auth.totp_required` (exit 2). A wrong or expired code fails with `auth.totp_invalid` (exit 2), not `auth.forbidden`. `LIUM_NONINTERACTIVE=1` turns the prompt off.
