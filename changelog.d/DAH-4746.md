### Added
- `lium provider portal login` signs in a provider account that has an authenticator app. When the portal asks for the code, the CLI prompts for it in a terminal ("Authenticator code (or a recovery code)"). Scripts pass it with `--totp-code <code>`, which also takes a recovery code. Without a terminal or `--totp-code`, the sign-in fails with `auth.totp_required` (exit 2). The same prompt appears when another provider command has to sign in again. `lium provider config set-email` takes `--totp-code` too, since it signs in again. A wrong or expired code fails with `auth.totp_invalid` (exit 2), not `auth.forbidden`. `LIUM_NONINTERACTIVE=1` turns the prompt off.
