### Changed
- `lium ps` shows a `#` column and `--format json` carries `index`: the row number other commands accept as a pod target. `ps` records the listing per shell (`~/.lium/last_ps.<parent pid>.json`), so another agent's `lium ps` in the same home directory does not redefine this shell's numbers.
- `rm`, `ssh`, `exec`, `scp` and every other command that takes pod targets translate a row number to the pod the last `lium ps` in this shell showed on that row and act on that pod wherever it is in the live list (`GET /pods` has no fixed order). The number is refused with `stale_pod_index` (exit 2), naming the pod that was seen, when there was no `ps` in this shell, the listing is older than 10 minutes, or that pod is no longer listed — instead of acting on whatever pod the account-wide list now has in that row. A number that is literally a pod's name still matches that pod.
- `lium rm` prints what each row number resolved to (`1 → eager-wolf-aa (name: train)`) and, on a terminal without `--yes`, asks before removing pods selected by number.

### Added
- `lium rm --name-only` and `LIUM_NO_POD_INDEX=1` (all commands): treat numeric targets as names only.
